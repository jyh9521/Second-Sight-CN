# 009：语音字幕、底板与字库清晰度

## 008 的用户反馈

用户在 008 确认以前缺失的一些字幕已出现，另有有声无字幕的位置。截图 3840×2160，显示“外面那个开关应该能开门。”，文字两侧有深色竖线，笔画发虚，字内标点偏上。截图不是转储的同一对白帧，不混用两者证据。

用户提供的转储仅离线读取，不复制或上传。SHA-256：`5b54dba78ab4be3c115e67dff71f9999272d7531016be184c66d2fbafaa3878f`。主映像头和 8 个未改原指令指纹匹配；转储 ASI 与 008 本地 ASI 的 162192 字节 .text 按基址重定位后完全一致，且渲染、语音 hook 已落点。

实际字段：字幕选项=1、HUD=1、tick=1；原生 active BS=2491、display gate=8；活动 owner 同样为 BS2491，flags=14、handle=-1、剩余约 3.617 秒。BS2491 对应“啊，不行！我怕是撑不下去了。我感觉好……虚弱……”，与截图上另一句不同。008 只接受有独立音频 handle 的事件，因而跳过该独立渲染路径；快照中原生选择器已选中该行，但单一状态不能证明原生最终画了像素或精确定位声音来源。

## 修改及验证边界

- 游戏内对白：以真实事件 2 为入口，保留正 handle 的音频 ready 检查；只对原生旗标 8 已置位、且剩余时间有限并大于零的 -1 句柄接收时长型 cue。0、其它负值、未置旗标/已结束记录仍拒绝。仍沿源绑定 BS、字幕选项、结束事件和 HUD 重置，不按关卡计时或强开原生字幕选项。
- 字幕竖线：移除新增渲染器的 `0x638B40` 纹理底板调用（该原生过程按切片绘制），保留文字及混合状态保存/恢复。未改其它游戏 UI 的原生底板。008 在正 handle 夹具提交一次底板；009 提交零次。
- 字库：`SLP3` 的自有六页 BC2 字库从 512²/16 像素格升级到 1024²/32 像素格，保持 6144 槽、同一 ID 表、字体与引擎几何/字距。统一思源黑体左基线，字格纵向基线 24.5 px，27 px em，空白格边一个像素；不再独立垂直居中每个字形。保留引号、问号等字形原本相对高度，不改译文标点内容。
- 兼容：旧 512² 语言包仍走旧 UV；新包六页必须是同一尺寸。四处原字节预检后只改自有字形分支的 UV：0x612603、0x612606、0x612615、0x612621。32 像素格两轴取样中心为 0.5–31.5，无跨页末尾越界。其它纹理、渲染尺寸和原版字体采样不改。

离线回放使用编译 ASI、真实 x86 语音更新和排版，设备、GPU 提交、翻译数据加载边界由夹具控制。字库检查解压最终语言包 DDS 的实际 alpha，验证了全部图集格边透明及句号/逗号/顿号位置；原生指令验证三个 UV 坐标（含最后一格）。真实游戏是否补齐这一场景、竖线是否消失，以及菜单/PDA 等渲染面最终清晰度由用户验证；不宣称解决所有没有文本 ID 的语音或原生 UI 自身的低分辨率。
