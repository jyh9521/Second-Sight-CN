# 踩坑记录

这里记录已经观察到的边界和容易误判的做法。静态证据、离线结果和游戏内验收分开记录；新增结论需要带输入版本和复现方法。

## UTF-8 译文不等于引擎支持 Unicode

普通文字路径以单字节字符为主，原有特殊分支使用“逗号 + 十进制字形编号”。直接把 BS 字符串换成 UTF-8 只能证明字节写入成功，不能证明游戏能显示中文。当前 PoC 将标记改为 `0x1F`，每个可见译文字符编码为四位编号，数字本身也编码，防止原解析器把相邻数字吞入编号。编辑态文本、游戏字节和字形映射须分层，字宽与子串边界同时适配。

## 日文字库不是即插即用的中文方案

EXE 引用了 `jpnfont1`～`jpnfont6`，但扫描全部 PAK 没找到这些成员；初始化还存在跳过记录和关闭模式的路径。原六页×256 格只是名义布局，不代表 PC 分支完整、可直接使用或容量足够。当前六页×1,024 格扩展是在核对七处分页/行列指令和真实尺寸 UV 归一化后实现，不是简单把 DDS 放大；完整画面仍待用户验收。

## FusionFix 的设置语言不是游戏语言

`TextLanguage` 只控制 FusionFix 设置界面。其开发者覆盖层字体也不等于游戏字体。中文字形与 BS/PDA 数据仍需独立实现，不通过改一行 cfg 宣称兼容。

FusionFix 已接管部分文字/HUD 入口；再写一个跳转可能覆盖旧钩子。必须确认预期原字节、加载顺序和链式调用，或选择不冲突的接入位置。

## 两个 dinput8.dll 不能并排同名加载

原安装中的文件是 GOG Input wrapper，FusionFix 提供的是 Ultimate ASI Loader。替换前须记录 hash、保存原文件并提供恢复步骤；不要把“文件存在”当成已经正确加载了两套功能，也不要改动原安装作为第一轮实验。

## P4CK 中成员名不一定唯一

`anim/animg2.pak` 存在 5 处同名成员。应保留目录顺序和条目索引，名称歧义时拒绝按名字替换，不能用字典去重丢掉条目。

P4CK 头部 `0x0C` 是文件名池长度，不是目录总长度。成员相对偏移、载荷偏移与目录偏移也不能混用。完整结构见[文件格式](FILE_FORMATS.md)。

## 共享字符串偏移不是独立存储

BS 多个 ID 可共享同一个字符串地址。原地覆写可能连带修改其他 ID；变长文本还可能破坏后续字符串。探针采用追加后重定向指定 ID，验证其余 ID 不变。ID 0 还承担当前解析器识别表长的锚点，不能把探针误当作任意 ID 的完整导入器。

## PDA 的 raw 后缀不代表纯文本

PDA 是结构化资源，不应扫描到可读内容就逐段替换。现有解析器用页/行/段和指针字段定位文本；PoC 在解析/重定位后替换字段指针，不依赖只拦截底层读文件，以免加载/缓存路径绕过替换。离线重建的 `MODIFIED_FILE.raw` 只是验证产物，不是当前运行时安装文件。

字体 `.raw` 名称也会在 PC 加载器内改为 `.dds`。以实际加载代码和成员数据判定格式，不靠后缀推断。

## 多份相同资源不代表全部同时生效

BS 存在于两个 arcade 包，PDA 在剧情包重复。当前字节相同不证明优先级，也不证明单改一份能覆盖全流程。需要用户场景反馈和可追溯资源映射，避免只见到一处成功就声明全游戏覆盖。

## 离线通过不等于游戏通过

回写后的字节、目录、hash 和回滚均正确，仍可能遇到加载器对齐、缓存、编码、布局和生命周期问题。初始追加探针使用保守对齐，但没有完成游戏加载验收。

用户明确要求自行启动游戏；自动化不为了补截图擅自启动。中断启动、进程出现、标题窗口出现也不能自动记为中文菜单、字幕或 PDA 通过。

## 小样本不等于覆盖整个功能

初始 PoC 的 11 条剧情候选没有全部完成场景对应，不能写成“11 条实测字幕”；四条 PDA 也只是一个 Isolation 任务页，不是四页。这些是历史限制，当前已汇总 5,957 条 BS 和 447 段 PDA，并支持源绑定控制码/模板；但全量目录统计仍不等于每条文本的可达性或布局验收。早期构建器拒绝控制码和 `%`，后续通过具体调用契约开放，不能靠删除原格式标记让检查通过。

离线宿主的错误 EXE 身份拒绝是预期通过条件；它既没有运行游戏，也没有证明游戏内钩子安装成功。测试时应同时保留模块日志、包版本和用户截图。

## 证据来源要准确

初始深层反编译 provider 因 JDK 配置失效未运行；相关细节来自 pefile/Capstone 的静态分析。记录真正执行的工具和输入 hash，不把工具入口存在写成该工具已完成反编译。

初始评估和旧验证日志是历史快照。后续 Git 提交、工具能力或运行状态变化时，更新当前文档，不倒写旧实验结果，也不删掉失败线索。

## 改名加载器不等于共享渲染路径已兼容

PoC 002 把 UAL 改名为 `dsound.dll`，让 ReMade 保持 `dinput8.dll`。UAL 的 dsound 序号转发会按系统导出名称适配，不能只用原始导出序号断言冲突；另一方面，两个文件名不同也不能证明 D3D9 钩子、字体和缓存已兼容。仍需用户手动验证音频、输入、三类中文画面和高清材质。

## 证据快照保留原字节

Windows 上 `Path.write_text()` 默认换行转换可能把 LF 清单改成 CRLF，即使重新解析后的 JSON 完全一致，文件 hash 仍会改变。清单快照直接复制文件，不用重新序列化代替 byte-exact 副本；合成测试覆盖该情况。

旧测试包的配置可能已被用户修改。保留并记录实际状态，不为了让旧清单通过而重置配置。PoC 001 的无边框/60 FPS 配置保持不动；002 重新取固定输入目录的默认配置。

## Python 调用 Windows PowerShell 的模块路径

从 PowerShell 7 环境经 Python 调用 Windows PowerShell 5.1 时，可能继承不同版本的模块路径，导致 `Get-FileHash` 未被正确导入。包内开关和清理脚本先把当前 `$PSHOME/Modules` 放到模块搜索路径前端；不修改机器的永久环境设置。

## 不要在重建测试包时丢失用户要求的窗口模式

003 复制上游默认配置导致 `WindowMode=0`，没有延续用户需要的无边框。004 起打包策略显式生成 `WindowMode=2` 的输出，保留其他配置字节及上游输入，记录前后 hash；旧包配置不追溯重置。窗口模式测试与崩溃归因分开，设置正确也不能证明菜单实机通过。

## Windows 跨盘证据目录

CI 仓库可能在 D:，临时证据目录在 C:；`os.path.relpath` 对跨盘路径抛出异常。配置回滚脚本同盘使用相对路径，跨盘使用带引号的绝对工具路径，并有不实际创建其他盘文件的回归测试。该修正只影响离线证据脚本，不修改测试包运行内容。

## 不按整个 PDA 文件统一删除句号

PDA 同时包含任务短指令和剧情简介。内容角色和逻辑句子的现行判断遵循 [STYLE](../locales/zh-CN/STYLE.md)，不按整个文件或显示行处理。看到英文简介并不证明短任务页钩子失败，先核对稳定页/行 ID。

## PDA 短样本可见，不等于长文 token 正确

原 PDA 独立逐词/行首跳白路径会把 0x1F 当空白；005 在具体调用点修正，同时绕过未知容量的全文展开全局缓冲区。不要仅提高构建上限。动态键名还经过64字节双键格式化，中文按每字5字节编码时必须同步约束键名。005 的具体字节见[历史文本契约](research/TEXT_CONTRACTS_005.md)；当前完整 wrap、复合终端和 HUD 后置拷贝见[全量容量研究](research/FULL_TEXT_CAPACITY.md)。

## 完整译文不等于直接指针替换全部开放

255 字节是部分 UI 拷贝的界，不是 BS 格式界。长文只有在邮件、纸张或终端消费链闭合后才分档放行；五段拼成一条消息时还必须算总长度。未定位的 14 条旧文本保留完整译文，但不改原 BS 指针，只在已审计调用者处精确匹配使用。不要为做出“全表注入成功”的计数而取消这些限制，也不要为了 255 字节删掉剧情信息。

纸张按像素折行后仍有 256 字节逐行栈拷贝，一个中文 token 占五字节，因此需要同时限制像素宽度与行编码字节。HUD 的全局槽和后续栈各有 512 字节边界，仅扩大其中一处不足以解决问题。

## 文本表、EXE 字面值和图像文字分开取证

PC 版权画面通过 `legal_english512.dds` 绘制，翻译 BS313/314 不会改变该图片。载入提示也属于图片，现用独立的思源黑体绘制链及源 hash 契约生成；不把原图改绘或修改高清材质当成默认做法。

EXE 中能扫描到英文不代表 PC 玩家会看到。旧暂停/Controls 界面已按实际分支检查，不为未使用路径增加补丁；快速滚动、按钮不可用则有已定位的消费者与局部容量，当前作防御性覆盖；实际 PC 触发可达性尚未完全闭合。对应 EXE 翻译只改完整 push 的指针立即数，仍核对原串和固定版本，不能全局搜索替换同文字符串。

## 编号和版本不能替代交付门槛

004 的部分可见中文、005 的 832 条 BS、历史测试数都保留为各自检查点。当前必须先完成全部汉化和离线收口，再提供完整包；不能把更新文档、生成语言包或通过部分测试写成 006 已交付。自动化不为补充证据自行启动或附加游戏。

## 字库页正确并不代表绘制批次正确（007）

仅校验字符ID、页号和UV不足以证明最终取字正确。006中这些值都正确，但整句顶点直到最后才提交，纹理已变成最后一页，导致“新游戏→新人戏”等错字。回归必须覆盖一条字符串内部的多页交替、Latin和空格切换、裁剪、阴影预遍历；要运行真实回调与新ASI指令，而非仅用相同公式互相验证。不要用重排字库、替换字体或关闭高清掩盖批次生命周期缺陷。

同一个固定EXE也可能选择另一份英语BS。源文比较失败应先核对当前资源身份；只支持已验证完整hash的显式别名，不移除原文校验，不强改用户语言配置。

## 逐句规则不能用整条文本代替

旧检查器遇到整条含逗号或多句就豁免，导致后续独立短句漏报；回归样本为「保存完成，请继续。按键返回。」。修正后按 [STYLE](../locales/zh-CN/STYLE.md) 处理逻辑句子和引号层级，游戏适配保留控制码/换行。含糊缩写与括号产生待审项，不静默删除。迁移结果见[采用记录](BASELINE_ADOPTION.md)。
