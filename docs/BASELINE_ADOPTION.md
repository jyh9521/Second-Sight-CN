## 具体冲突与处理

| 旧条款/现状 | 新规范及影响 | 处理依据 |
|---|---|---|
| TRANSLATING「非剧情文本只有一句话」；旧检查器整条含逗号或多句即豁免 | 用户明确逐个逻辑句判断；旧逻辑漏报多句中的单句 | 以用户最新明确准则与 STYLE 为权威；不改写个人偏好。新策略已接入原检查器和构建门禁；未自动改译文 |
| 旧 AGENTS/core 是忽略的本地副本 | 基准要求团队/CI可读、来源可追踪 | 替换旧生效规范并跟随源码提交，原副本仅作本地证据 |
| 通用示例使用 UTF-8 源 hash、opaque ID 与状态枚举 | 本项目用 CP1252 字节 hash、稳定分组 ID 和旧 status | 保留已验证的源绑定语义，记录适配差异；不重算指纹、不把旧字符串状态提升为 reviewed |
| 文档「全量首轮译文完成」「测试包」容易被理解为完整验收 | ACCEPTANCE 将数据、资源、运行、发行分开；test release 也有 G3/G4 前置条件 | 保留历史条目计数，当前称本地实验候选；翻译、审校、运行覆盖分别列示 |
| 模板要求安装事务/完整输入门禁 | 项目目前是隔离副本打包、部分输入强契约 | 规范已适用但功能未齐；不据此声称 G0/G4 通过 |

## 本轮首个可验证目标

在不启动游戏、不修改原始输入、译文和冻结包的条件下，完成规范迁移、可复现逐句标点回归及现状清单。

基线样本「保存完成，请继续。按键返回。」：旧检查返回未发现问题，新检查定位第二句末尾句号；另测换行、省略号、引号嵌套、缩写、控制码投影及非中文策略。副本回滚恢复旧行为，工作树保留新检查器。

当前目录审计：27 条记录、45 处明确句号问题、6 处上下文待审。逐句审计退出 2（fail），不是 0。`translation_checks.py` 同样拒绝这些记录，语言包构建在输出写入前终止。回归测试验证“能发现已知问题”，**不将这 51 项当成允许发布的白名单**。CI 的工程测试与严格目录验收分作不同任务，后者仍会失败，直到待审项逐条关闭。

6 处含糊项：BS2411 年份缩写撇号；BS3275/4067 姓名首字母点；BS3632 组合文本未闭合括号；BS4509/4510 编号右括号。先核对源文及实际组合语境，再记录 ID 绑定的判断，不全局删除点号/括号或放宽策略。

完整命令、字面输出、退出码和回滚证据在本地 `build/baseline-adoption-20261117/VERIFICATION.txt`；本轮源码验证汇总见[验收快照](ADOPTION_VALIDATION.md)。不重建 008，不改变 006/007 的输入、字体或兼容配置。
