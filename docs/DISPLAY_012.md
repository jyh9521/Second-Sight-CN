# 012：提高菜单、地图和 PDA 可读性

## 011 的实机反馈

用户确认 011 的 F1 作弊菜单能用。012 只改其简体中文窗口标题为《第二视界》作弊菜单，不改 ASI、快捷键及三个开关。菜单仍默认不加载。用户的 4K 截图另外指出：主菜单以及地图／PDA 不够清晰；过场左下角时间／地点很小；左下角“治疗”文字在屏幕底边被截断。以下是 012 的离线证据，尚未升格为游戏内验收。

## 修复范围

| 路径 | 012 改动 |
|---|---|
| 中文字库 | 六页思源黑体由 1024×1024／32 px 字格改为 2048×2048／64 px 字格，从轮廓重新栅格化，不放大旧位图。保留字形 ID、字宽、行距、位置、标点基线、透明边距和 011 前端阴影；按 DDS 尺寸区分 512/1024/2048 取样坐标，旧包仍可读 |
| 地图与 PDA | 高分辨率下，把已定位的终端私有渲染池从 256×256 提升到 512×512。原逻辑坐标与交互域保持 256；只在此池、只在提交前成对变换 XYZRHW 的屏幕坐标与逻辑裁剪框。保留原 UV、3D 顶点、其他目标、全局后处理和扫描线 |
| 过场时间／地点 | 两个专用字体调用点内，字号按显示高度从 720 行开始增加；原生先测量整个多行文字再定位，不移动对白字幕、保留淡入淡出 |
| 左下角超能力／武器文字 | 在既有放大字体的最终描边调用前，用原生度量确定全行高度，必要时向上移动，保留文字、字号、位置横轴和图标；对有效裁剪下界保留描边空间 |

## 技术证据

- PDA 渲染入口 `0x583A40` 经 `0x583A74` 调终端 `0x5D18E0`；后者选用 `0x5CFD30` 返回的私有池 ID 并绑定目标，地图绘制保留 256 逻辑单位。池分配点为 `0x5CE45B`，设备渲染目标尺寸来自真实纹理描述符。注册保持原设备路径，固有小窗口用原 256。
- 缩放只处理已绑定池成员、确认渲染尺寸为 512、确认刚记录的动态 VB 及已写顶点范围、且 FVF 表示预变换顶点的批次。`0x40DE6E` 记录原动态锁指针；`0x40E21B` 在原 VB Unlock 前缩放。裁剪使用原游戏的 inclusive right/bottom 接口，物理 viewport / 其他目标不二次缩放。关于预变换顶点与设备空间的区别，参见 [Direct3D 9 像素映射](https://learn.microsoft.com/en-us/windows/win32/direct3d9/directly-mapping-texels-to-pixels)。
- 过场角标 `0x5443B0` 使用第 24 号字体，绘制点 `0x5444D5` 仍调用原生入口。过场对白使用不同范围。超能力／武器共用的选中标签调用点为 `0x57BAEB`，使用调用期间的第 18 号样式。
- [离线回放](../tools/replay_display_012.py)使用真实字串 BS776（两行时间地点）和 BS697（治疗）以及编译 ASI 进行原指令对照；低分辨率／非目标 / XYZ 是负对照。纹理分配、设备裁剪及文本最终提交用夹具记录，不是 D3D 设备或游戏画面验收。[字体工具](../tools/verify_font_polish.py)重新打开打包 DDS 并检查透明边、标点位置和最后一格的原生 UV。
- 不声称消除主菜单滤镜的扫描线、提升地图底图原素材的分辨率，或覆盖未进入该私有池的其他屏幕。实机需验证地图和 PDA 在换页／退回时是否干净、板面边缘和交互区域是否仍对齐。测试包出厂关闭可选作弊菜单，使用方法见随包 `TESTING.md`。
