# Second Sight 汉化可行性评估

日期：2026-11-17。评估对象：本地 GOG PC 游戏及项目目录提供的 FusionFix。

## 结论

**值得立项；资源与文本层可行性较高，中文显示与 FusionFix 共存属于主要技术风险。整体按中高难度工程规划。**

推荐“保留原版 FusionFix + 独立本地化模块 + 结构化语言数据”，不在第一阶段分叉整套 FusionFix，也不先做全量翻译。若中文实现必须和 FusionFix 修改同一个入口，再把这部分做成小型集成模块。

当前完成的是静态评估、格式验证及隔离副本实验，不是可玩的中文补丁。游戏、FusionFix 和 Hub 均未启动，未向安装目录写入补丁。

## 1. 当前项目与版本基线

- 初始本地目录是本地化工程模板，`src/`、`tools/`、`tests/`、`locales/zh-CN/` 原先只有占位文件；目录没有 `.git`。本次没有初始化、提交、推送或发布。
- 2026-11-17 打开的 [GitHub 项目页面](https://github.com/jyh9521/Second-Sight-CN) 显示空仓库。应把当前阶段称为技术预研，而不是已有汉化框架的完善。
- 已读取项目 `AGENTS.md`、本地化标准及构建、翻译、技术、格式、已知问题和授权文档；通用工具与语言数据继续分离。
- 原 EXE：5,484,544 字节，x86，文件版本 `0,10,0,0`。
- EXE SHA-256：`4092a8d1fb042dffe9fb95e2185f32cb80390299145e8d453a5e909a06d35fda`。
- 游戏目录已有 GOG Input wrapper `dinput8.dll`，1.0.0.5195；SHA-256 `6c059a19692ac72a8b11b4972f67d1afc6765092181a8bacf539345a08abe65e`。最终安装器需明确处理它与 UAL 的关系，不能把两个同名 DLL 当作可并排加载。

## 2. 已确认的资源与文本

| 部分 | 本次观察 | 判断 |
|---|---|---|
| 外层封包 | 258 个 `P4CK` PAK，24,930 个目录条目，15,083 个不同成员名；总计 929,239,032 字节 | 已全量验证目录、文件名和数据范围；没有外层解密障碍 |
| 主文本 | `data/strsspxe.bs` 等 6 个语言/地区变体，出现在 `pak/arcade/l_101.pak` 与 `l_103.pak` | 两包内同名文本逐字节一致；运行时加载优先级待确认 |
| 主文本结构 | 6,526 个小端 u32 偏移，随后是 NUL 结尾字符串池 | EXE 加载器也以 `0x65F8` 为偏移表长度，静态交叉印证 |
| 英文规模 | 6,425 个非空 ID；5,484 个不同非空字符串；不同文本约 36,738 个英文词元 | 包含复用、未使用、调试和其他平台遗留内容，不等于最终翻译任务清单 |
| PDA/任务资料 | `data/pdaps_[aefgis].raw`，包含任务目标、人物、武器等可读内容 | 每个后缀在 17 个剧情包重复；a/e 内容相同；内部结构仍需专用解析 |
| 常规字体 | impact：256×256；book/booklight：128×256；均为 DXT3 DDS | 对应资源分别有 19/20/19 份，按名称的各份 hash 一致 |
| 日文字库 | EXE 引用 `jpnfont1`～`jpnfont6`；本次全部 PAK 成员名中未发现这些资源 | 有代码线索，但不是现成可用字库 |
| 脚本/过场 | VM 脚本、41 份 `csinfo.txt` 等 | `csinfo.txt` 是场景/动作清单，不能直接当字幕文件翻译 |

主文本与 PDA 可能有内容重叠；不把 PDA 和 36,738 词直接相加。相同原文也不能自动合并翻译 ID，应保留上下文。

已确认英文池中存在 `0x09`、`0x0A`、`0x0B` 控制字节。编辑源可采用 UTF-8 JSON/TSV，但运行时编码应由构建器转换，不能直接把 `.bs` 全体改成 UTF-8 并宣称中文可用。

## 3. 中文显示：优先攻克的问题

### 已验证的静态代码

- 普通绘制路径以单字节查表为主；Windows 宽字符 API 导入不证明游戏正文支持 Unicode。
- 日文字形路径识别“逗号 + 十进制字形编号”，不是 UTF-8 解码器。
- 字形按高位选页、低位选 16×16 网格；六个已声明页面对应 **1,536 个名义字位**。
- 绘制和宽度计算中都能找到该特殊路径，这使复用它有价值。
- 但日文字体记录的 `flags=0x9F` 被初始化加载条件跳过，模式变量在已找到的初始化调用中设为零。
- `.raw` 字体资源名会在 PC 加载器内转换为 `.dds`；文件后缀字符串不能独立决定实际资产格式。

### 高置信度推论与待验证事项

优先尝试激活/扩展原有字形编号路径，比一开始重写整个渲染器更有针对性。但 **1,536 字位不是已验证容量，也不能预设足够覆盖中文**。必须验证编号边界、逗号与数字的歧义、字宽、行高、分页、换行、截断及所有调用者。

若该路径在 PC 中不完整，第二方案是独立解码/字形查找/宽度计算模块，必要时接入 D3D9。菜单、字幕、PDA 和电脑终端须分别验收；一次标题画面成功不代表全游戏成功。

静态证据与可复现脚本位于 `build/assessment-20261117/native/`。REA 已确认目标身份，但深层 provider 的 JDK 配置失效；具体反汇编证据来自 pefile/Capstone，不是伪称已完成的 Ghidra 反编译。

## 4. FusionFix 兼容路线

### 本地版本

- `SecondSight.FusionFix.asi`：`13.11.2026.1802-7bce79f`，GitHash `7bce79f`。
- ASI SHA-256：`939d0bbc6dacca73b4323fa018ba11d04a87dde5073e795b5914db85d6158430`。
- `dinput8.dll`：Ultimate ASI Loader 10.0.2；Hub：0.1.9.25。
- 对应 [源码提交 7bce79ffaeee61f95db59a68b35a150cd8644223](https://github.com/ThirteenAG/WidescreenFixesPack/tree/7bce79ffaeee61f95db59a68b35a150cd8644223/source/SecondSight.FusionFix)。本轮不以更新的 HEAD 代替这个基线。

### 已核实边界

- cfg 的 `TextLanguage` 是 **FusionFix 自身设置语言**；现列 en/fr/de/it/es，不是游戏正文汉化开关。
- FusionFix 修改窗口、镜头、HUD、过场和 D3D9 等行为。其 ImGui/字体实现属于开发者覆盖层，不是游戏 `.bs`/PDA 的中文字库。
- 原 EXE 中 `0x612BC0` / `0x613330` 两个文字入口被其 HUD 逻辑用于坐标调整。汉化不能盲目再次覆盖入口而破坏原钩子。
- 观察到导出 `InitializeASI`、`AsiSettings_GetApi`；没有据此确认存在供外部插件使用的游戏本地化 API。内部回调接口不等于稳定外部 ABI。
- 当前源码核查没有找到现成的 BS/PDA/PAK 资源覆盖实现；资源替换入口仍由汉化工程验证。
- 本地 UAL 有整文件 overload 导出，可列为资源重定向候选，但不自动理解 P4CK 内部成员；先通过文件访问记录验证实际命中，再决定是否采用。若中文模块持有 D3D9 纹理，还要与 FusionFix 协调设备 reset 后重建。

### 推荐决策

| 方案 | 评价 | 采用条件 |
|---|---|---|
| 同一 UAL 加载原 FusionFix 与独立 locale ASI | **首选**；责任清晰、方便升级和回滚 | 避开已被接管的入口，或验证链式调用和加载时序 |
| 为 FusionFix 加小型本地化集成模块 | 备选；能够协调共享渲染/宽度入口 | 独立插件确有不可消除的双钩冲突，并固定对应提交 |
| 整套 fork 后长期维护全部修复 | 暂不优先 | 有持续维护需求且上游集成路线不适合 |
| 只改贴图或 `TextLanguage=zh` | 没有证据支持作为完整路线 | 不作为中文支持的判定依据 |

如果复用上游源码，按真实上游许可和来源管理；上游 license 文件与本地版本资源的许可文字存在差异，需保留记录，不能仅凭 DLL 元数据判定。`FusionFix/` 是用户提供的本地依赖目录，已加入忽略清单，不把其整套二进制误作自有源码提交。

## 5. 已执行的副本实验

输入是 `pak/arcade/l_103.pak` 的隔离副本。

- 目标字段：`data/strsspxe.bs` 的 **ID 850**，`New Game` → `Localization probe`。
- 先追加新字符串并重定向该 ID，再追加重建的 BS 并更新 P4CK 的目录位置、目标成员偏移/长度。
- 15 项合成单元测试通过，包含共享字符串偏移、增长、多字节原样保存、坏偏移、终止符、封包边界、重复成员名和未知 flags。
- 全部 258 个安装 PAK 的目录结构检查通过。
- 无改动回写逐字节一致；变长回写只改变 1 个文本 ID，另 6,525 个 ID 和另外 6 个 PAK 成员内容保持一致。
- 执行 `ROLLBACK.sh` 恢复另一个副本，再确认逐字节等于基线；修改产物仍保持修改状态。
- 原安装 PAK/EXE 未改变。以上是**离线格式验证**，不等于游戏接受重建包，更不等于中文渲染或 FusionFix 兼容验收。

产物均在 `build/assessment-20261117/`：`MODIFIED_FILE.pak`、`DIFF_FILE.json`、`VERIFICATION.txt`、可执行 `ROLLBACK.sh`。日志包含实际命令、输入、字面输出和退出状态。

## 6. 建议实施顺序与验收门槛

1. **最小中文 POC**：固定本次 EXE + FusionFix hash；保留原版；确定 BS/PDA/字体实际加载路径与资源优先级；显示中文菜单、短字幕、PDA 长段及中英混排。验证数字、中文标点、换行、按键提示、宽字符和重复文本。
2. **渲染与兼容**：优先原字形路径；所需字集统计后再确定分页/扩容。分别测试 FusionFix HUD 约束、过场黑边、4:3/16:9/超宽与 1080p/1440p/4K；验证读档、关卡切换和恢复原版。
3. **工程化工具链**：补齐 PDA 格式和资源关联；建立稳定 ID、原文 hash、语境、翻译状态、控制码校验、字形覆盖、布局预算；通用工具接受 `--locale`，汉语资料放 `locales/zh-CN/`。
4. **内容生产**：主文本清理/分类后开展翻译；保留文件/邮件/任务的语境；检查贴图中的文字。先自动化再人工校对，避免把无上下文机翻当最终译文。
5. **全流程 QA 与发行**：覆盖剧情章节、电脑/PDA、字幕时间、战斗提示、存档、不同 FusionFix 配置；发布差分/构建器，不发布完整游戏文件；在干净输入上复现。

规划建议（非承诺工期）：先给中文与 FusionFix POC 一个 **2–5 个工作日的研究窗口**，用上述三类屏幕作为继续投入的门槛。如果需要重写字体/布局，应在该阶段后重新估期。主文本已有约 3.7 万英文词量级，再加资料与通关 QA，应按多周项目安排，而非几小时换字库。
