# 菜单与 PDA 扩展的文本契约（005）

本记录来自固定 GOG 文件的**只读静态分析**，不代表游戏内显示、分页或输入已经通过。没有启动、附加或操作游戏进程。实现与测试结果以对应源码及构建记录为准；下文将原始事实和适配方案分开。

## 输入与方法

- `secondsight.EXE`：5,484,544 字节，SHA-256 `4092a8d1fb042dffe9fb95e2185f32cb80390299145e8d453a5e909a06d35fda`。
- `pdaps_a.raw`：79,622 字节，SHA-256 `f684ffe987026172b5a69f82e11ee6426190bf629939596cad3f6571b098f6d7`。
- 已解析 PDA：68 页、447 个非空显示段、333 个不同文本值。机器标识符和图片引用不属于这 447 段。
- REA `open_binary` 本轮再次确认输入身份；`analyze_function(0x580660)` 返回 `provider_unavailable / runtime_missing`（配置中的 JDK 路径失效）。没有反编译结果，不将下面的 Capstone 输出写成 REA 伪代码。
- 下列地址为 VA；读取通过 PE 节映射换算，不运行原指令。完整本地反汇编、地址核验和模型输出保存在忽略目录 `build/menu-pda-005/contracts/`。

## 1. PDA 使用独立的逐词路径

### 已验证的原始控制流

`0x580A70` 遍历一行的内容段。文字段经 `0x580640` 展开按键后，传给 `0x5806F0` 测宽、折行和绘制。原始调用链不是只经过通用 `0x611C70` 的折行函数。

`0x580660` 的接口为 `const char* __cdecl(char* destination, const char* source)`，返回第一个未消费的源字节：

1. 它复制一个词，**包含**第一个有符号字节值不大于 `0x20` 的分隔字符；`0x0B`（VT）例外，不在该字节停止。
2. 遇源 NUL 时停止并为目标补 NUL，不消费源 NUL。
3. 目标第一个字节为 VT 且第二字节为 `E` 时，将整个词替换为 `0x53FEA0(3)` 的返回文本；首 VT 为 `J/K` 时在词末加一个 ASCII 空格。
4. 没有目标容量参数。调用者 `0x5806F0` 的单词栈区为 **200 字节**（从局部区到栈 cookie 的距离）。

`0x580610` 的接口为 `const char* __cdecl(const char*)`。它跳过有符号值不大于 `0x20` 的前导字节，但不跳 VT。`0x580832` 在换行后调用它。

因此，现有 `0x1F + 4 位数字` 在这两条 PDA 路径中被误当成空白：逐词函数会在 marker 本身停止，行首处理会直接跳过 marker。短任务页显示正常不能证明长段落的 token 边界正确。

### 适配契约

- 逐词适配将一个合法 marker token 视为完整单位；中文可以逐字折行。
- 普通词遇 marker 前停止，避免把 marker 吞进前一个 ASCII 词。保留原始分隔空格，不把原控制码当文字译掉。
- 单次目标输出采用不超过 190 字节的保守界限，另有 NUL 空间；长普通词也需按完整单位分块，不依赖原函数无界复制。
- 换行后跳白函数增加 marker 例外，保留 VT 原例外。
- 格式损坏的 marker 必须在语言包加载前拒绝；运行辅助函数仍不得无限循环或跨 NUL 读取。

## 2. 长文本不能只提高 450 字节限制

### 已验证的原始缓冲区

| 路径 | 原始行为 | 容量结论 |
|---|---|---|
| `0x610260` ExpandKeys | 总是逐字节复制到全局 `0x9E38A0`，没有“无 VT 直接返回”分支 | 没有获得声明容量，禁止凭相邻地址推定安全上限 |
| `0x580640` PDA 展开 | EAX 入参，调用 ExpandKeys，再把结果无界复制到 `0x9654A8` | 没有获得全局容量 |
| `0x5806F0` PDA 单词 | 栈中暂存一个词后测宽 | 200 字节，可由栈布局验证 |
| `0x580A70` PDA 段绘制 | 给 `0x5806F0` 传入本地行输出区 | 2,048 字节，可由地址与 cookie 距离验证 |
| 通用 wrap `0x611C70` | 单词临时区约 512 字节，循环比较 500；marker 数字内层复制没有逐字节上限 | 属单词工作区，不是整段 PDA 的统一容量 |
| UI `0x4BEAA6..0x4BEAC4` | bounded-copy 255 字节后在 `+255` 写 NUL | BS 仍保留 255 编码字节限制，不能靠 token 计数补救已截断的字节 |

PDA 的 2,048 字节输出区在**每个段**开始清空；一行可能有多个链接段，不需要把整行所有段的长度误当单个缓冲区容量。但任何一个段经动态按键展开后的最坏长度都需要受约束。

### 建议的局部适配

1. 对带本地化 marker 的 ExpandKeys 输入，改用插件持有的稳定缓冲区；无 VT 时可直接返回稳定输入指针。
2. 每个原 VT+opcode 单独交给原函数的 trampoline 展开，立即复制其结果。这样继续使用原按键配置和原 opcode 语义，不再让完整长译文进入未知大小的全局区。
3. 非本地化输入继续原契约，不将新传输格式泛化到未核实的原文。
4. PDA 的两处展开调用改到 EAX 入/出的薄适配器，结果存放在**独立于通用 ExpandKeys 的持久区**。测宽/计数会再次调用 ExpandKeys；复用同一缓冲区会覆盖正在遍历的 PDA 文本。
5. 语言包构建、加载和辅助函数同时做边界校验。建议 PDA 每段**最坏按键展开后不超过 1,800 字节**，为 2,048 字节输出和 NUL 留余量；不是宣称引擎已支持任意 4 KiB 长段落。

该方案仍需用户验收长文折行、链接选中、段间接续、滚动、不同分辨率与动态重绑定。标点禁则（如避免中文句号出现在行首）属于后续排版改进，不能与 token 完整性混为一谈。

## 3. 精确接入点与约定

| VA | 原始字节 | 接入类型 |
|---|---|---|
| `0x58074D` | `E8 0E FF FF FF` | 调用 `0x580660`，cdecl `word(char*, const char*)` |
| `0x580832` | `E8 D9 FD FF FF` | 调用 `0x580610`，cdecl `skip(const char*)` |
| `0x580C2A` | `E8 11 FA FF FF` | 链接文字调用 `0x580640` |
| `0x580C4C` | `E8 EF F9 FF FF` | 普通文字调用 `0x580640` |
| `0x610260` | `53 8B 5C 24 08` | ExpandKeys 入口；完整的 `push ebx; mov ebx,[esp+8]` 两条指令 |

两个 `0x580640` 调用的输入与输出均为 EAX，没有栈参数；原函数可以破坏 ECX、EDX 和 flags，保留 EBX、ESI、EDI、EBP。x86 薄适配器可将 EAX 压栈调用普通 cdecl 帮助函数，清理该参数后返回；不可错误地按原调用者栈上的首参数取文本。

所有接入点都需先核对上表原字节和原 EXE 身份，再统一安装。创建 trampoline 时复制完整指令。冲突拒绝与部分安装回滚仍是必需项。

## 4. VT opcode 与键名长度

PDA 源文本观察到 `E/J/I/G/2/4/K`。原 `0x610260` 使用范围 `1..I` 的跳表：

- `1/2/3/4/G/H/I` 等项调用按键名称函数。
- `A/B` 将两个动作的按键名称用 `%s,%s` 拼接到约 `0x208` 字节的独立区。
- `D/E` 取 BS 6518/6519，即 `movement keys` / `the mouse`。
- `J/K` 不在范围内，原函数跳过这两个字节。不要让新适配器擅自发明其图标或键名语义；译文可以自然表达操作，但原控制序列保持原样。

`0x540680` 的键名缓存多数存放 BS 文本指针，并不把完整译文复制进短字符槽；但下游 `0x53FDE0` 使用 **8 个轮转的 64 字节槽**与无界格式化：

```text
单键：'%s'
双键：'%s','%s'
```

双键固定开销 5 字节，加 NUL 后，任意一个键名编码长度限制为 29 字节可保证 `29 + 29 + 5 + 1 = 64`。实现可以取更保守的 27 字节。此限制必须针对所有可能被绑定的物理键名，而不只是默认键位。不要将“NumPad Enter”全部按每字符 5 字节编码而忽略此路径。

两个动作各返回最多 63 字节时，`%s,%s` 的拼接最长为 127 字节加 NUL，落在原 `0x208` 区内。动态占位符与 VT 必须保持原字节/顺序，不能作为普通字形编码；未确定契约的格式串仍应拒绝。

## 6. 离线回归至少覆盖

- 原始 PDA tokenizer 模型确实拆开 marker，新 tokenizer 保留 token。
- 行首空白后 marker 不被跳过；英文、引号、空格和 marker 相邻时不吞字符。
- 最大单词/段边界、截断 marker、未知 opcode、空输入、重复调用、不同缓冲区生命周期。
- 两个 29 字节键名和双键格式恰好占 64 字节含 NUL；更长键名被构建器拒绝。
- 原字节校验、五处新增点与现有修改区不相交，以及自有内存恢复。
- BS 255 字节限制继续有效，PDA 的 1,800 字节限制以最坏动态展开长度而非仅文件长度计算。
- 字符集容量、原文 hash、VT/占位符序列和未翻译机械字段保持不变。

离线模型与自有宿主通过只能证明上述契约，不代替用户的实际游戏测试。

## 7. 实现复审补充

本轮对 `src/text_transport.h`、`src/localization.cpp` 的新增五处接入独立复审：EAX 薄适配器、cdecl 参数清理、ExpandKeys 入口 trampoline 的五字节指令边界，以及 PDA 与通用展开结果使用不同持久区，均与上述静态契约一致。PDA 展开后再次检查 1,800 字节，避免只检查传输长度；输入含 marker 且不含 VT 的快速路径直接返回稳定原指针。

对原 `0x6103CC` 的 25 字节索引表和 `0x61039C` 的 12 个目标地址作了逐项读取：`5/6/7/8/9/C/F` 都落在 `0x61037C`，`J/K` 经范围检查落在同一默认路径；这些项均只前进源指针两字节，不产生输出。即便某条通用提示把 `VT6` 放在 Back 旁边，也不据文字标签推翻这个 PC 分支的真实语义。

使用 27 字节物理键名上限时，严格预算可分为：`1/2/3/4/G/H/I` 最多 59 字节，`A/B` 最多 119 字节，`D/E` 按 BS 6518/6519 的受控上限计算，已确认删除的项为零。菜单每个 VT 都按 127 字节预算虽然保守，却会错误拦住正常的多键提示。原 `0x4BEA70` 消费者从参数直接取文本，先执行 255 字节复制，再调用 count/ExpandKeys；这个顺序已静态核对，但不是所有 BS 调用者的通用证明。

另读取 `0x89152C` 的 123 个物理键映射条目及五个鼠标缓存槽：本轮对应译文全部标注键名身份，连同保持原文的物理键简称，最大长度为 25 编码字节（“小键盘逗号”），没有超过 27 字节。完整 ID/长度清单仅保存在本地 `contracts/key-cache-audit.json`。

复审发现的长 ASCII 后缀问题已经反馈：仅按“后续还有 marker”决定是否使用有界分词会遗漏最后一个 marker 之后的长动态后缀；实现现增加普通词长度探测，超过界限走有界帮助函数，短词保留原函数的特殊控制行为。回归建议同时覆盖实际 wrapper 的分派条件，不只测试纯帮助函数。通用截短/排版调用者、所有布局和运行期缓冲区生命周期仍需实际验收，不把这次静态复审写成游戏测试通过。
