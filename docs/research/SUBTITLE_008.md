## SUB-001 原因与最小修复

过场循环使用 style 21，原生样式 `x/y=1`，中文版字形几何高度为 `16 × 0.87 × style.y`，因此提高输出分辨率后仍约 13.92 像素。这个样式还有其他消费者，永久放大共享样式会影响菜单/PDA 等界面。

新增 [subtitle_layout.h](../../src/subtitle_layout.h) 只在已审计的过场字幕循环使用私有样式副本：`Style.x/Style.y *= RenderHeight / 480`。测量、换行、行距和绘制共用同一副本；出口恢复先前字体指针、序号和 descriptor，原样式表不写入。无 locale 文本或中文字面值进入这个通用适配。

| 地址 | 必须匹配的原字节 | 修改及边界 |
|---|---|---|
| `0x543031` | `E8 5A D5 0C 00` | 将 SetFont 调用转到 beginCutscene，保留原函数调用及返回值 |
| `0x5431E8` | `D9 05 B4 74 96 00` | 所有 cue 分支的汇合出口；恢复状态，重放 FLD 后回 `0x5431EE` |

沿用已有事务补丁器的版本/原字节预检、写入及回滚。没有写原 EXE；没有改 FusionFix 的 `0x612BC0` / `0x613330` 文字入口；没有修改已有测试包。

### 可证伪检查与回放边界

1. 固定像素假设：五种分辨率 × 7/72 字的基线只有两个 480 高样例满足同比例高度，2/10，退出 1
2. 只放大最终绘制的负对照：高度 10/10，但测量宽度不一致，整体仍退出 1
3. 完整候选：实际编译的字号 hook、wrapHook、transport::wrap、std::string 与原生测量共同执行；上述十例加 0 cue / 2 cue，共 12/12，退出 0
4. 共享样式副作用：每例核对原 style21 字节不变；修改路径恢复指针、字体序号和 descriptor；出口通用寄存器/flags 不变
5. 隔离恢复：另一个 ASI 文件副本恢复 007 hash；独立 Unicorn 内存恢复两个字号补丁点后，布局 cases 与基线一致；修改产物保持不变

使用 Python 3.14、固定 Unicorn 依赖和 MSVC x86 `/W4 /WX /Brepro`。回放执行真正的原生过场布局，不用 Python 重写布局算法。场景/cue/BS 表、边距及字形载荷是合成边界；字幕开关、security cookie、最终 GPU 提交和 CRT 分配/atexit 的操作系统边界被替代。真实 wrapHook 的初始化器、字符串实现及 wrap 算法仍执行。它不是截图渲染或安装/卸载测试。

联合基线使用新构建中**未改变的 007 wrap 代码**，不安装字号两点；不是启动整个旧 007 ASI。回滚保留 wrap 入口，只撤销字号两点，隔离字号变量。另有真实 007 ASI 的独立宿主检查和文件 hash 恢复。

2880×1800 联合回放：比例 3.75，几何字高 52.2 像素；72 字样例换为两行、测量宽 2609。此前仅原生 wrap 的研究输出为 2714，已由实际 wrapHook 联合验证替代。原 atlas cell 仍为 16 像素，放大采样可能发软；实际清晰度、长句语义断行、同屏多 cue 互不遮挡不在此次合成通过声明内。

## SUB-002 已有对白，不先假定需要转录

[inspect_dialogue_routes.py](../../tools/inspect_dialogue_routes.py) 校验原 EXE、原 BS hash、五条源文指纹及八处原指令：BS2472–2475、2508 有对应原文及译文。当前源表有文本不等于该声句已进队列或显示。

已证调用链：

- 关卡初始化状态范围 2472–2475；当前值先递增再播放，不能断言 2472 就是用户听到的第一句
- 主角 `0x562A71 → 0x5B1D90 → 0x453680`
- NPC2508 `0x563B5E → 0x453680`
- `0x453680 → 0x456900 → 0x456850` 创建语音队列；`0x456D00` 播放并决定字幕标志；`0x456610 → 0x63F6A0` 选择当前字幕
- `0x63F830` 检查 active BS、显示 gate 及字幕选项后，进入原生换行/测量/绘制；上层 HUD 路由也有门控

已排除一个静态原因：主角传入 queued flags 为 0（`0x5B1DA9`），NPC2508 为 2（`0x563B4B`），经 `0x4536F9` / `0x453700` 传递到入队节点，二者都不含 `0x100` 禁字幕位。后续距离/可见性、声音状态、模式、优先级和 HUD 状态仍可能改变路径；不据静态文本存在就强行覆盖全部门控。

队列 flags 与 owner flags 不是同一字段。非空文本/范围判断通过且无 `0x100` 时，owner 的 display bit8 被设置；`mode==2` 会清除，`mode==1` 且 audio handle>0 也会清除。`0x456610` 还检查事件2、owner bit4 和音频等待条件；通过后才把 `owner.flags & 8` 交给字幕选择器，成为 `0x9FE8DC`。这些是静态分支含义，不是对 007 实际字段值的推断。

关键状态：`0x9649E8` 语音到字幕模式、`0x91C88C` 字幕选项、`0x8AA0E8` HUD gate、`0x9FE868` active BS、`0x9FE8DC` display gate、`0x9FE8D8` owner、owner+8 BS ID、owner+0x48 flags、`0x8BDBD4` priority、`0x9FE8D4` fade。距离/说话者状态及语音队列自身未必都在最小快照内；必要时再按录下的指针扩展只读分析。

[inspect_subtitle_dump.py](../../tools/inspect_subtitle_dump.py) 仅读取明确提供的 DMP。检查记录的主模块基址、大小、时间戳、PE 头和八处未修改指令后才解码字段；未记录内存保持 unknown。模块路径只作候选提示，不冒充加载模块完整 hash。
